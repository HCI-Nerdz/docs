= ClearType per-monitor settings
:description: Subpixel layout (RGB/BGR) as a product-representation problem—UI that offers per-monitor tuning vs renderers that often apply one global orientation.

*ClearType per-monitor settings* are the Windows affordances that *look* like each display can have its own subpixel antialiasing layout (RGB, BGR, or grayscale), while large parts of the text stack still behave as one session-wide choice.

In plain language: the tuner asks which monitor; GDI mostly ignores that question; DirectWrite only honors it when the app opts in.

== Core claim

A settings UI that enumerates monitors for ClearType implies *per-panel honesty*. Stock Windows only partially delivers that honesty. Tools that stamp one layout on every display are often *more* accurate about OS reality than a wizard that writes decorative per-display keys.

== Why it is an HCI topic

This is the same class of bug as link:https://hci-nerdz.github.io/blog/product-representation-is-the-bug/[product representation]: the engine and registry have more than one structure; the first-class UI narrates a simpler story than renderers implement.

* **Representation:** monitor picker in `cttune.exe`
* **Partial truth:** `HKCU/HKLM\SOFTWARE\Microsoft\Avalon.Graphics\DISPLAYn` can hold distinct `PixelStructure` values (documented for WPF)
* **Contradiction:** `SPI_SETFONTSMOOTHINGORIENTATION` / `FontSmoothingOrientation` under `Control Panel\Desktop` is session-global for GDI; many DirectWrite apps never call `CreateMonitorRenderingParams`

Users with an RGB laptop panel and a BGR external display learn the lie as color fringing on whichever side lost the global vote.

== Guidance (honest defaults)

* Treat **Better ClearType Tuner** as a global RGB/BGR/grayscale + contrast tool. Do not expect it to fix one panel without affecting the other.
* Treat **`cttune.exe`** as able to differentiate Avalon per-display keys, not as a guarantee of independent GDI layouts.
* For mixed subpixel hardware, verify with the actual apps you read in (GDI classic UI vs DirectWrite/WPF vs browsers). MacType and similar exist when inbox stacks cannot express the panel.
